Localization node ROS2 · Python
localization_node.py 
class LocalizationNode(Node):
    def __init__(self):
        super().__init__("localization_node")
        self.pose_sub = self.create_subscription(
            PoseStamped, "/pose_modelcars",
            self.pose_modelcars_callback, 10)
        self.robot_pose_pub = self.create_publisher(
            Pose, "/robot_pose", 10)

    def pose_modelcars_callback(self, msg):
        self.robot_pose_pub.publish(msg.pose)

Advanced AI courseHochschule Coburg · Oct 2026with Gaurav Basheer

When our model failed, we found out why

We taught a detector to spot traffic cones in the university's model city, using photos I took and labelled. With the training settings we were assigned, the model got worse instead of better. We traced the cause, proved it with a second run, and fixed it.

Detection accuracy (mAP), same dataset0.007→0.474

In transfer learning, how you train matters as much as what you train on.

I collected the 147-image dataset in the model city and labelled every cone, car and person myself.

Root cause: the settings, not the data
SettingGivenEffect
Learning rate0.05Wiped out what the model already knew
Frozen layersnoneThe whole network was retrained, so it forgot its features
Batch size4Noisy updates and random spikes
Epochs75Learning stopped after epoch 8
Reading the loss curve tap the markers
  • 1Huge loss spikes in the first epochs. The learning rate was far too high for fine-tuning and broke the model's predictions.
  • 2Flat from about epoch 8. The model stopped learning, and later learning-rate drops changed nothing.
  • 3Spikes at epochs 32 and 61. With only 4 images per batch, one odd batch throws the model off.
